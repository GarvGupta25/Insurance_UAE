# Phase 1 synthetic walkthrough

This walkthrough exercises the current application without insurer, Groq or Razorpay accounts. Use the local setup in `README.md` first. The API, worker, frontend and Supabase services must all be running. Open `http://127.0.0.1:5173`; the API health endpoint is `http://127.0.0.1:8000/health` and the database readiness endpoint is `/ready`.

1. Create a local account in the website and sign in. The dashboard should show an empty policy portfolio. Start a new insurance profile.
2. Enter a synthetic applicant such as “Amina Example”, a past birth date, Indian nationality, UAE resident, Dubai, no diagnosed conditions, non-smoker, no maternity need, UAE geography, a future start date, self payer, AED 12,000 annual budget, flexible maximum, and monthly budgeting. Save the structured editor. Chat may be used too; without a Groq key it gives an honest manual fallback. With a Groq key, any proposed profile changes still require review. Voice recording, when configured, returns an editable transcript before sending; read-aloud is optional.
3. Get the indicative quote. Compare the three **fictional** plans and download the PDF. The first plan should rank highest for this example. Inspect the official research links separately; they do not provide these fictional premiums.
4. Select a supported plan with Easy Fill. Review the complete saved-data mapping, then open Broker workspace and approve or change the supported fictional plan. Return to the application, review the new exact payload, confirm it, and submit to the **in-app carrier sandbox**. The result is a demo policy, not insurer-issued cover.
5. Open Payments. Create an instalment order and choose “Simulate successful payment.” One receipt should appear and the first instalment should show paid in the sandbox. Failed/cancelled simulations leave the balance due. No card or real money is involved.
6. Open Nearby care. The three sample facilities are fictional. Try denying browser location permission: emirate selection and list view should still work. The map loads OpenStreetMap tiles only if explicitly opened.
7. Open Servicing on the demo policy. Submit a pre-authorisation or claim using a synthetic reference and amount. The deterministic decision and benefit ledger appear in history. A denied decision can be appealed; Broker workspace can uphold it or record a permitted correction, which replays the ledger without replacing history.
8. Return to Overview and run a fit reassessment. Broker workspace can record retain-current-policy or a future fictional-plan recommendation. This never switches the active policy.
9. Return to the dashboard. The policy remains saved. Add an existing policy with only its name, insurer and start date; it should appear as **unverified** without inferred benefits or premium.

For an automated authenticated API check, run `uv run python scripts/live_smoke.py` from `backend/` while Supabase, the API and worker are running. It creates a synthetic account, runs intake through a queued agent, quotes, submits a sandbox application, records one local payment and checks the saved receipt. It prints no credentials. This script cannot pass when Docker/Supabase is stopped.

The public API contract is generated by FastAPI at `http://127.0.0.1:8000/openapi.json` and can be inspected at `/docs`. Authentication uses a Supabase Bearer access token. State-changing POST commands use an `Idempotency-Key` header; profile PATCH uses `expected_version`; application submission requires the preview's `payload_hash` plus `declarations_confirmed`. The route families are `/api/me/profile`, `/api/cases`, `/api/runs`, `/api/voice/transcriptions`, `/api/documents`, `/api/catalogue`, `/api/sources`, `/api/quotes`, `/api/applications`, `/api/policies`, `/api/providers`, `/api/instalments` and `/api/payment-orders`. Payment-provider webhooks are configured separately at `/api/webhooks/razorpay`.

Live AI transcription/chat, Razorpay test checkout, real insurer plans, actual provider-network membership and verified policy notices require credentials or third-party evidence. No demo transaction activates insurance.
